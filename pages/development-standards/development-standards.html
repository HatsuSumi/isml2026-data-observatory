ISML 2026 前端开发基线

本项目前端尽力遵循的开发规范

核心思想：减少浏览器回流和重绘，防范 XSS 风险，提升代码可维护性与执行效率。

1. DOM 节点创建

少用大段 innerHTML，固定结构优先写在 <template> 中，再通过 cloneNode(true) 克隆。

不推荐

拼接 HTML 字符串，或频繁使用 document.createElement() 在循环中逐个创建复杂 DOM。

container.innerHTML = `<div>${user.name}</div>`;

items.forEach(item => {
  const card = document.createElement('div');
  const name = document.createElement('span');
  name.textContent = item.name;
  card.appendChild(name);
  container.appendChild(card);
});

推荐

模板只解析一次，结构和样式分离，克隆后用 textContent 填入内容。

const template = document.getElementById('user-card');
const fragment = template.content.cloneNode(true);
fragment.querySelector('.name').textContent = user.name;
container.appendChild(fragment);

2. 渲染函数返回值

render 函数尽量返回 Node 或 DocumentFragment，不返回 HTML 字符串。

不推荐

返回反引号拼接的 HTML 字符串，尤其不要把外部数据直接插进字符串。

export function renderCard(data) {
  return `<div><p>${data.name}</p></div>`;
}

推荐

从模板克隆 DOM 节点，填充文本后返回 Node 或 DocumentFragment。

export function renderCard(data) {
  const fragment = cardTemplate.content.cloneNode(true);
  fragment.querySelector('.name').textContent = data.name;
  return fragment;
}

3. 样式修改

状态切换优先使用 classList，动态数值使用 CSS 变量，减少直接写入多个 style.xxx。

不推荐

连续写入多个 element.style.xxx，导致样式权重过高且触发更多样式计算。

panel.style.color = 'red';
panel.style.fontSize = '16px';
panel.style.backgroundColor = 'yellow';

推荐

状态变化用 classList，动态数值集中写入 CSS 变量。

panel.classList.add('is-warning');
document.documentElement.style.setProperty('--panel-size', '16px');

4. 批量插入 DOM

大量节点插入时先进入 DocumentFragment，最后一次性挂到容器，避免循环中反复触发布局计算。

不推荐

在循环里反复 appendChild 到真实页面容器。

items.forEach(item => {
  const node = renderItem(item);
  list.appendChild(node);
});

推荐

先把节点放入 DocumentFragment，最后一次性插入页面。

const fragment = document.createDocumentFragment();
items.forEach(item => fragment.appendChild(renderItem(item)));
list.appendChild(fragment);

5. 事件监听

列表、菜单等重复元素优先使用事件委托，只在父容器绑定一次监听。

不推荐

给大量子元素逐个绑定监听，后续新增节点还要重复绑定。

document.querySelectorAll('.item').forEach(item => {
  item.addEventListener('click', handleItemClick);
});

推荐

监听父容器，通过 event.target.closest() 精准定位触发元素。

list.addEventListener('click', (event) => {
  const item = event.target.closest('.item');
  if (!item) return;
  handleItemClick(item);
});

6. 定时动画

动画和高频视觉更新使用 requestAnimationFrame，不要用固定间隔模拟帧率。

不推荐

使用 setInterval 固定 16ms 执行动画，页面后台仍可能浪费资源。

setInterval(() => {
  moveElement();
}, 16);

推荐

使用 requestAnimationFrame 跟随浏览器刷新节奏执行视觉更新。

function animate() {
  moveElement();
  requestAnimationFrame(animate);
}

requestAnimationFrame(animate);

7. 数据处理

读取深层数据用可选链和空值合并；多分支业务优先用策略映射。

不推荐

写多层 if 防空，或用 || 把空字符串和 0 误判为默认值。

if (data && data.user && data.user.info) {
  name = data.user.info.name;
}

const count = data.count || 10;

推荐

用 ?.、?? 处理空值，多分支逻辑用对象映射表达。

const name = data?.user?.info?.name ?? '游客';
const count = data?.count ?? 10;
const handler = strategyMap[type] ?? strategyMap.default;

8. 数据请求

缓存要按数据特性设计：静态数据会话复用，动态列表设置 TTL，实时数据不缓存。

不推荐

每次都重新请求，或把所有数据无限期缓存。

async function loadEvents() {
  return fetch('data/events.json').then(res => res.json());
}

localStorage.setItem('events', JSON.stringify(events));

推荐

静态数据会话缓存，动态数据设置过期时间，实时数据保持即时请求。

const cached = cache.get(key);
if (cached && Date.now() - cached.time < ttl) {
  return Promise.resolve(cached.data);
}

9. 列表更新

列表变化时基于 data-id 做精准更新，尽量不要整块清空重渲染。

不推荐

数据一变化就清空容器重建，导致滚动位置、焦点和局部状态丢失。

container.replaceChildren();
items.forEach(item => {
  container.appendChild(createNode(item));
});

推荐

用稳定 data-id 查找节点，只更新变化字段，新增或删除必要节点。

const node = container.querySelector(`[data-id="${item.id}"]`);
if (node) {
  updateExistingNode(node, item);
} else {
  container.appendChild(createNode(item));
}

10. 交互反馈

根据场景选择 Debounce、Throttle 或 RAF，避免一刀切处理高频交互。

不推荐

所有高频事件都不限制，或全部加防抖造成输入和滚动反馈迟钝。

input.addEventListener('input', renderResults);
window.addEventListener('scroll', updateProgress);

推荐

搜索用 Debounce，滚动和 resize 用 Throttle，视觉动画用 RAF。

input.addEventListener('input', debounce(renderResults, 300));
window.addEventListener('scroll', throttle(updateProgress, 100));
场景策略时机
搜索框输入Debounce300ms
滚动 / resizeThrottle100ms
拖拽 / 动画requestAnimationFrame跟随屏幕刷新率
按钮连点Debounce500ms

特邀原则：Fail Fast 原则（Fail Fast Principle）

关键条件不满足时立即抛出明确错误，禁止使用降级处理、容错逻辑、if 语句块、逻辑或运算符、三元运算符、可选链或空值合并运算符隐藏架构问题，让依赖缺失、DOM 结构错误、参数无效、配置错误等问题在开发阶段早期暴露，避免在生产环境中出现不可预测的行为。

不推荐

以下七种写法都会把关键错误隐藏起来，导致问题延迟到更晚阶段才暴露。

1. 降级处理

const button = findSubmitButton() || createFallbackButton();

2. 容错逻辑

try {
  startApplication();
} catch (error) {
  console.warn('启动失败，继续显示空页面', error);
}

3. if 语句块

const button = document.querySelector('.submit');
if (button) {
  button.addEventListener('click', submit);
}

4. 逻辑或运算符

const timeout = config.timeout || 3000;

5. 三元运算符

const url = config.apiUrl ? config.apiUrl : '/fallback-api';

6. 可选链

const modal = page?.components?.modal;

7. 空值合并运算符

const endpoint = config.endpoint ?? '/default-endpoint';

推荐

启动阶段立即校验关键依赖、DOM 和参数，失败时抛出包含上下文的明确错误。

const button = document.querySelector('.submit');
if (!button) {
  throw new Error('启动失败：缺少 .submit 按钮');
}

if (!Number.isFinite(config.timeout)) {
  throw new Error('配置错误：timeout 必须是有效数字');
}

代码审查清单

  • 是否存在大段 innerHTML 赋值或模板字符串拼接用户数据？
  • render 开头的函数是否返回 Node / Fragment 而非 String？
  • 是否有超过 3 层以上的三元运算符或 if/else 嵌套？
  • 循环内是否直接操作 DOM？
  • 列表渲染是否使用事件委托？
  • 动画效果是否使用 requestAnimationFrame？
  • 数据请求是否设计了合适缓存策略？
  • 列表数据变化时是否基于 data-id 最小化更新？
  • 搜索、滚动、拖拽、按钮提交等高频交互是否使用了合适策略？
  • 关键依赖、DOM、参数和配置不满足时，是否立即抛出明确错误，而不是使用降级或容错逻辑隐藏问题？
